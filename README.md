# Conference Halls API

API для роботи з конференц-залами. Вона зберігає список залів, приймає бронювання і рахує вартість оренди.

Репозиторій: https://github.com/alexanderlysak42/ABP_TEST

## Що вміє API

- Додавати, змінювати, дивитися та видаляти зали
- Додавати до залу додаткові послуги (проєктор, Wi-Fi, звук)
- Шукати вільні зали за датою, часом і кількістю місць
- Бронювати зал і одразу рахувати ціну
- Показувати звіти: скільки зал заробив і скільки годин його використовували

## Стек

.NET 10, база даних PostgreSQL 17, Swagger (сторінка для перевірки запитів), Docker Compose.

## Запуск

```bash
cp .env.example .env
docker compose up -d --build
```

Після запуску:

- Swagger: http://localhost:8080/swagger
- Перевірка, що програма працює: http://localhost:8080/health

Усі запити, крім Swagger і `/health`, потребують заголовок `X-Api-Key`. Його значення береться зі змінної `API_KEY` у файлі `.env`. У Swagger ключ вводять через кнопку **Authorize**.

База даних працює в окремому контейнері. Потрібні таблиці створюються самі під час запуску.

Зупинити проект, зберігши дані: `docker compose down`.
Зупинити й видалити всі дані: `docker compose down -v`.

## Запити

| Дія | Адреса | Що робить |
|---|---|---|
| GET | /api/halls | Список залів |
| GET | /api/halls/{id} | Один зал |
| POST | /api/halls | Додати зал |
| PUT | /api/halls/{id} | Змінити назву, кількість місць, ціну за годину |
| DELETE | /api/halls/{id} | Видалити зал (не можна, якщо в ньому є бронювання) |
| GET | /api/halls/available | Знайти вільні зали: `date`, `startTime`, `endTime`, `capacity` |
| GET | /api/halls/{hallId}/services | Список послуг залу |
| GET | /api/halls/{hallId}/services/{id} | Одна послуга |
| POST | /api/halls/{hallId}/services | Додати послугу до залу |
| PUT | /api/halls/{hallId}/services/{id} | Змінити послугу |
| DELETE | /api/halls/{hallId}/services/{id} | Видалити послугу |
| POST | /api/bookings | Забронювати зал |
| GET | /api/bookings, /api/bookings/{id} | Усі бронювання / одне бронювання |
| GET | /api/reports/revenue | Заробіток залів за період: `from`, `to` |
| GET | /api/reports/utilization | Скільки годин зали були зайняті за період: `from`, `to` |

Приклади:

```bash
curl -H "X-Api-Key: $API_KEY" \
  "http://localhost:8080/api/halls/available?date=2030-01-10&startTime=10:00&endTime=14:00&capacity=50"

curl -X POST http://localhost:8080/api/bookings \
  -H "X-Api-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"hallId":1,"date":"2030-01-10","startTime":"10:00","durationHours":4,"serviceIds":[]}'
```

## Правила

- Ціна залу рахується за кожну годину окремо:
  - з 06:00 до 09:00 знижка 10%;
  - з 09:00 до 12:00 і з 14:00 до 18:00 звичайна ціна;
  - з 12:00 до 14:00 надбавка 15%;
  - з 18:00 до 23:00 знижка 20%.
- Ціна послуг завжди однакова. Її додають до суми один раз за бронювання.
- Бронювати можна з 06:00 до 23:00, тільки цілими годинами і в межах однієї доби.
- Два бронювання одного залу не можуть перетинатися в часі. Якщо одне закінчується о 14:00, а інше починається о 14:00, це можна.
- До бронювання можна додати лише послуги того залу, який бронюють.
- У пошуку показують зали, де місць не менше, ніж потрібно, і які вільні в цей час.
- Зал, у якому вже є бронювання, видалити не можна.

## Початкові дані

- Під час запуску створюються три зали з умови завдання: Зал A (50 місць, 2000 грн/год), Зал B (100 місць, 3500 грн/год), Зал C (30 місць, 1500 грн/год).
- Для кожного з них додаються послуги: Проєктор (500 грн), Wi-Fi (300 грн), Звук (700 грн).
- У режимі розробки (так запускається `docker compose`) ще додаються три пробні бронювання на завтра. Вони потрібні, щоб одразу було видно пошук і звіти.
- Повторний запуск нічого не дублює.
- Якщо видалити стандартну послугу залу, після перезапуску вона з'явиться знову.

## Опис структури

- Код розділено на три частини: контролери приймають запити, сервіси виконують всі правила, база зберігає дані.
- Дані від користувача перевіряються. Якщо щось не так, програма відповідає зрозумілим повідомленням.
- Коди відповідей: 400 (неправильний запит), 401 (немає або неправильний ключ), 404 (нічого не знайдено), 409 (конфлікт, наприклад зал уже зайнятий).
- Доступ захищено одним спільним ключем `X-Api-Key`.
- Час бронювання зберігається без часового поясу.

## Що можна покращити

- Окремі ключі для різних користувачів
- Обмеження кількості запитів
- Захист від ситуації, коли двоє одночасно бронюють один зал
- Скасування та перенесення бронювань
- Нові звіти: які послуги замовляють частіше, у які години більше бронювань
- Автоматичні тести
